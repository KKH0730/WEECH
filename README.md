# 📺 위치 (WEECH)

유튜브를 **같이 보는 3D 라운지**. 코루라이브의 '객장' 구조를 참고했습니다.
벽에 걸린 TV 에서 실제 유튜브가 재생되고, 모두의 재생 위치가 자동으로 맞춰집니다.

```
node server.js      →   http://localhost:3000
```

three.js 를 `public/vendor/` 에 동봉했습니다. **CDN 없이 로컬에서 돌아갑니다.**
(서버 자체는 외부 패키지 0개 — three.js 는 브라우저용으로만 쓰입니다)

---

## 흐름

**로비** 에서 둘 중 하나를 고릅니다.

| | 입력 |
|---|---|
| **방 만들기** | 닉네임 · 방 제목 · 유튜브 링크(영상·재생목록 여러 개 가능) |
| **방 참여하기** | 닉네임 + 목록에서 고르기 또는 5자리 코드 |

링크는 `watch?v=`, `youtu.be/`, `/shorts/`, `/embed/`, 생 영상 ID 를 모두 인식합니다.
**재생목록 링크(`list=`)도 서버가 펼칩니다.**

| 종류 | 처리 |
|---|---|
| 일반 재생목록 `PL…` `OL…` `FL…` | InnerTube `/next` 로 곡 목록을 통째로 받습니다 (실패하면 공개 페이지 긁기) |
| **믹스 / 라디오** `RD…` | **펼치지 않고, 공유한 씨앗 영상 한 곡만** 담습니다 — 아래 참고 |
| 씨앗 영상 | 공유한 사람이 들려주려던 곡이므로 **맨 앞으로** 옮깁니다 |

### 믹스(`RD…`)를 펼치지 않는 이유

`RD` 로 시작하는 ID 는 고정된 재생목록이 아니라, 유튜브가 씨앗 영상을 기준으로
**호출할 때마다 새로 만들어내는 무한 라디오**입니다 (응답에 `isInfinite: true`).
같은 링크를 1초 간격으로 두 번 받아보면 25곡 중 자리까지 같은 곡이 **4곡뿐**이고,
로그인 여부에 따라 개인화되어 공유한 사람이 본 목록과도 다릅니다.

그래서 펼치면 **목록에 없던 영상이 섞이고 순서도 뒤죽박죽**이 됩니다.
순서를 지키려면 `PL…` 로 시작하는 진짜 재생목록 링크를 쓰세요.

최대 50곡. 재생목록과 개별 영상을 섞어 적어도 **적은 순서가 유지**됩니다.
제목은 재생목록 페이지에서 읽고 없으면 oembed 로 채웁니다 — **둘 다 API 키가 필요 없습니다.**

## 방 — 22m × 16m (352㎡), 천장 8.8m

| 벽 | 무엇이 걸려 있나 |
|---|---|
| **정면** | **12m 스크린**(81㎡) + 그 오른쪽에 세로로 긴 **재생목록 전광판**(2.8×6.0m) |
| **왼쪽** | 액자 13점 + **실버 · 골드 버튼** 2점 (높은 천장에 맞춰 위쪽에도 한 줄) |
| **뒤쪽 천장** | **영사기** — 스크린까지 14.8m 를 가로지르는 빔이 재생 중에 보입니다 |

정원 20명이 **모두 앉을 수 있습니다** — 소파 5개(16자리) + 1인 의자 4개.

### 조명 — 전부 간접 조명

세워 두는 스탠드는 없습니다. 건축 조명만 씁니다.

- **천장 코브** — 벽에서 0.75m 안쪽, 천장 아래 0.3m 에 띠를 둘러 천장을 비춥니다.
  아래로 턱을 달아 광원이 직접 보이지 않고 천장만 밝아 보입니다
- **하단 간접** — 영화관 통로등처럼 벽 아래 10cm 높이를 따라 따뜻한 스트립이 깔립니다.
  소파 앉은 높이보다 낮아 눈에 직접 들어오지 않습니다

광원은 천장 4 + 하단 4 + TV + 전광판 = 10개로 묶어 성능을 지킵니다.

밝기는 `roomdef.js` 의 **`LIGHT`** 한 곳에서 조절합니다 — 노출·환경광·코브·하단·화면·전광판.
영화관처럼 어둑하게 맞춰 두었고, **화면이 방에서 가장 밝은 것**이 되도록 했습니다.
스탠드가 사라지면서 바닥 장애물도 줄어 **78%** 를 걸어 다닐 수 있습니다.

TV 앞 자리와 뒤쪽 라운지로 구역이 나뉘고, 러그 2장이 각각을 덮습니다.
테이블 2개, 책장 2개, 화분 4개, TV 양옆 스피커.

## 유튜브가 어떻게 벽에 붙어 있나

유튜브 영상은 iframe 이라 **WebGL 텍스처로 가져올 수 없습니다.** (CORS·DRM)
그래서 두 겹으로 겹칩니다.

```
  ┌─ WebGL 캔버스 (위) ─ 투명 배경. TV 자리에만 '구멍'을 뚫는다
  │                      NoBlending 재질이 그 픽셀을 알파 0 으로 덮어씀
  └─ CSS3D 레이어 (아래) ─ 같은 카메라 행렬로 iframe 을 3D 변환
```

둘이 **같은 투영 행렬**을 쓰므로 비스듬히 봐도 원근이 정확히 맞습니다.
구멍 메시는 깊이 버퍼에도 쓰기 때문에, TV 앞을 지나가는 아바타는 화면을 제대로 가립니다.

픽셀 → 미터 환산도 정확히 맞췄습니다: iframe 1280×720px × 0.009375 = **12.0m × 6.75m**.

### 두 가지 시점

- **라운지 뷰** — 아바타에서 12.5m 떨어져 내려다보며 공전합니다 (휠로 조절). 천장과 남쪽 벽은
  안쪽에서만 보이는 면이라, 위에서 보면 **인형의 집처럼 방 안이 들여다보입니다.**
- **시청 모드 (1인칭)** — `V`. 눈높이 1.56m 로 내려가 TV 를 정면으로 봅니다.
  내 아바타는 숨고, 화면 가장자리가 어두워지며 TV 에 집중됩니다. 드래그로 둘러볼 수 있습니다.

### 점프와 가구

`Space` 로 **0.62m** 까지 뜹니다. 소파와 테이블 윗면이 0.45~0.46m 라 **올라서서 걸어 다닐 수 있고**,
책장(1.55m)·화분(1.1m)·스피커(1.05m)는 넘지 못해 그대로 장애물로 남습니다.
떠 있는 동안에는 발밑보다 낮은 가구를 통과하므로 걸려서 막히는 일이 줄어듭니다.

가구 충돌은 **회전까지 반영한 사각형(OBB)** 으로 봅니다. 외접 사각형으로 근사하면
비스듬한 의자 주변에 양옆 19cm 씩 보이지 않는 벽이 생겨 걸리적거립니다.
아바타 충돌 반지름도 0.32m → 0.26m 로 줄였습니다.

### 흡착 화살

고무컵이 달린 장난감 다트입니다. 쏜 사람이 **three.js 레이캐스트로 맞은 지점과 법선을 계산해
그대로 중계**하므로 모두의 화면에서 같은 자리에 꽂힙니다.
꽂히면 잠깐 떨다가 **5초 뒤 서서히 사라지고**, 사람에게 꽂히면 그 사람을 따라다닙니다.

## 방 코드와 초대

좌상단의 **입장 코드** 를 누르면 코드가 복사되고, **초대 링크 복사** 는
`주소/?r=코드` 형태의 링크를 복사합니다. 그 링크로 들어오면 코드가 자동으로 채워지고
닉네임만 적으면 바로 입장합니다.

왼쪽의 **인원 버튼** 을 누르면 지금 방에 있는 사람 목록이 펼쳐집니다 (기본은 접힘).
방장과 나에게는 각각 배지가 붙습니다.

## 방장

- **재생 / 정지, 이전 · 다음 영상** (하단 바)
- **⚙ 방 설정** — 방 제목과 재생목록을 언제든 변경
- 방장이 나가면 **가장 오래 있던 사람에게 자동으로 넘어갑니다**

## 영상 동기화

서버는 `{몇 번째 영상, 재생중인가, 위치, 그 위치를 기록한 서버 시각}` 네 가지만 들고 있습니다.

1. 접속할 때 서버 시각을 같이 받아 **각자 시계를 보정**
2. 지금 있어야 할 위치 = `위치 + (지금 − 기록 시각)`
3. 실제 재생 위치가 **1.5초 이상 어긋나면 따라붙습니다** (1초마다 확인)
4. 방장은 5초마다 자기 실제 위치를 보내 흐른 만큼 보정

영상이 끝나면 자동으로 다음 곡. 마지막 다음은 처음으로 돌아옵니다.
브라우저가 소리 있는 자동재생을 막으면 음소거로 재생하며 **🔈 소리 켜기** 버튼을 띄웁니다.

## 구조

```
server.js              정적 서버 + WebSocket 룸 매니저 (의존성 0, RFC6455 직접 구현)
public/
  index.html           로비 · HUD · 모달 · importmap
  style.css            3D 레이어 + 유리질 UI
  roomdef.js           방 치수 · 가구 · 벽 배치 · 충돌  ← three.js 없이 순수 계산 (Node 에서 검증됨)
  scene3d.js           three.js 로 방을 짓는다 (재질 · 조명 · TV 구멍)
  avatar3d.js          둥근 카툰 2등신 — 캡슐 몸, 구 머리, 이름표/말풍선 스프라이트
  youtube.js           CSS3DObject + IFrame API + 재생 동기화
  game.js              카메라 두 모드 · 입력 · 네트워크 · 화살 · 전광판
  vendor/              three.module.js, CSS3DRenderer.js (동봉)
```

### 네트워크

- 10Hz 위치 브로드캐스트 (cm 단위 정수), 클라이언트에서 보간
- 방 하나 **정원 20명**, 동시 **최대 50개 방**
- 연결 전에 누른 버튼은 **큐에 담았다가** 열리면 전송
- 끊기면 2.5초마다 재연결하고 보던 방으로 **자동 재입장**
- 방이 비면 즉시 닫힘

### 서버가 막는 것

제어문자·방향 제어 문자 제거, 길이 제한(닉네임 12 / 방제목 40 / 채팅 120),
채팅 0.5초 · 화살 0.22초 쿨다운, 초당 120메시지 초과 시 연결 종료,
200KB 초과 프레임 거부, 정적 파일 경로 탈출 차단,
방장 아닌 사람의 재생·설정 조작 차단.

## 검증

```
lounge_server_test.js   35건 — 방 생성/참여/권한/동기화/정원 20명/방장 넘김
playlist_test.js        13건 — 실제 재생목록·믹스 링크 확장
lounge3d_test.js        132건 — 방 치수/벽 배치/충돌/가구 겹침/파일 무결성/픽셀-미터 환산
```

WebGL 은 Node 에서 돌릴 수 없어, **3D 렌더링 자체는 브라우저에서 눈으로 확인해야 합니다.**
대신 공간 계산과 배치는 전부 순수 모듈(`roomdef.js`)로 빼 검증했습니다.

## 다른 기기에서 접속하기

같은 공유기 안이라면 `http://<이 PC의 IP>:3000`. 포트 변경은 `PORT=8080 node server.js`.

## 운영 메모

- 방과 재생목록은 **메모리에만** 있습니다. 서버를 끄면 사라집니다
- 임베드가 막힌 영상은 자동으로 다음 곡으로 넘어갑니다
- 재생목록 확장은 InnerTube `/next` → **공개 페이지 긁기** 순으로 시도하므로
  유튜브가 응답 구조를 바꾸면 깨질 수 있습니다 (그때는 씨앗 영상 한 곡으로 폴백)
- 믹스(`RD…`)는 애초에 펼치지 않고 씨앗 한 곡만 담습니다
- 공개 운영 시 채팅 신고/차단 수단을 먼저 준비하세요
